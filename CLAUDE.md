# InBridge — project notes & change log

Reference for future work. Add a new entry at the top of the Change Log for every change.

## Architecture
- **Frontend + AI chat**: Next.js (App Router) on Vercel at https://inbridge.in. `/api/chat` runs the LLM failover chain (Anthropic, Gemini, Groq).
- **Backend**: Go (chi) in `backend/`, deployed on Render (free tier, Singapore) as `inbridge-api` — https://inbridge-api-2gwl.onrender.com. Handles auth, citizen profiles, service applications. Defined by `render.yaml`.
- **Data**: Supabase Postgres (Mumbai) via `DATABASE_URL` (use the *Session pooler* string), Upstash Redis via `REDIS_URL` (`rediss://`).
- Frontend reaches the backend through `NEXT_PUBLIC_API_URL` (browser-side fetches; JWT in `localStorage` as `inbridge_token`).

## Accounts and saved conversations
- Sign-up/login (optional) is ON by default; `NEXT_PUBLIC_AUTH_ENABLED=false` hides it. Session = JWT (24 h) + `{name,email}` in localStorage (`inbridge_token`, `inbridge_user`); helpers in `src/lib/account.ts` (`authFetch` clears the session and fires `inbridge:auth-expired` on 401).
- Chat history is local-first (`src/lib/history.ts`). When signed in, `src/lib/thread-sync.ts` mirrors it to the account: on login it pulls, merges (newest `updatedAt` per thread wins; equal time + different title = rename, local wins), pushes what the account lacks, then mirrors every save/rename/delete/clear (700 ms debounce, retries, `pagehide` flush). Status shown in the sidebar note.
- **Cross-account safety**: `inbridge_threads_owner` records whose threads are cached on the device. A different account signing in discards them; anonymous (pre-login) threads are adopted. Sign-out wipes the local copy but never deletes from the account.
- Known limit: no tombstones, so a thread deleted on device A returns if device B was offline and signs in later.
- Backend: `chat_threads` table (`db/migrations/009_chat_threads.sql`, RLS on) with `GET /api/v1/chat/threads`, `PUT|DELETE /api/v1/chat/threads/{id}`, `DELETE /api/v1/chat/threads`, all JWT-scoped (`handlers/threads.go`). PUT never overwrites a newer copy; 1 MiB / 400 messages per thread; newest 50 kept. Register generates the VID server-side (the form collects no ID), normalises/validates email, 409 on duplicate email; Login is case-insensitive and returns `citizen` like register.
- The old `conversations`/`messages` tables (005) are unused.

## Tavily usage tracking
- Every Tavily search (`searchGovPortals()` in `src/lib/rag-engine.ts`, up to 2 attempts per query) sends `includeUsage: true` and reports `{success, credits, latency_ms, search_depth, result_count, error_kind, request_id}` to the Go backend. The user's query text is NOT stored.
- Frontend: `src/lib/observability/tavily-usage.ts` (`buildTavilyRecord`, `trackTavilyUsage`) — fire-and-forget via Next `after()`, 2s timeout, swallows all errors, never delays or fails chat. Uses `INTERNAL_METRICS_URL`/`NEXT_PUBLIC_API_URL` + `INTERNAL_API_TOKEN` (server-side only).
- Backend: `POST /internal/telemetry/tavily` (insert, always 202) and `GET /internal/usage/tavily` (all-time + last-24h calls, failures, credits, avg latency) in `backend/handlers/tavily_usage.go`; both need header `X-Internal-Token`. Table `tavily_usage` from `backend/db/migrations/008_tavily_usage.sql` (also appended to `db/init.sql`).
- **The table must be created in Supabase (run migration 008 in the SQL editor) before data is stored**; until then inserts are logged and dropped, chat is unaffected.
- Check totals: `curl -H "X-Internal-Token: $INTERNAL_API_TOKEN" https://inbridge-api-2gwl.onrender.com/internal/usage/tavily`

## Health checks
- `GET /healthz` liveness, `GET /readyz` readiness (postgres, redis, LLM breakers), `GET /api/v1/health`.
- Render free tier sleeps when idle; first request can take ~15–50s. Warm it before demos.

## Known issues / ops checklist
- If login/signup return 500: check `/readyz`. `postgres: down` usually means the Supabase project is paused (restore it) or `DATABASE_URL` is not the Session pooler string.
- `www.inbridge.in` must be added under Vercel → Settings → Domains or it shows a cert error.
- Routes: `/` landing, `/chat`, `/services` (scheme finder over the myScheme snapshot), `/services/<slug>`, `/about`, `/privacy`, `/terms`. `/grievance` → `/chat?mode=grievance` (complaint drafter); `/status` and `/apply/*` → `/chat` (kept so old links don't 404). Use `curl -I` when checking status codes.
- InBridge is **independent** — never describe it as official / government / MeitY / NIC / verified in copy, metadata or prompts.
- Sign-in is hidden unless `NEXT_PUBLIC_AUTH_ENABLED=true` (backend DB was down; signup no longer sends DOB/gender/state, so those backend columns must be nullable before re-enabling).
- Chat contract: `src/lib/chat/protocol.ts` (data parts `sources`/`provenance`/`followups`, transient `phase`, metadata `createdAt/mode/language`). Request body `{messages, language, mode, focus}`.
- Theming: semantic tokens in `globals.css` (`bg-bg`, `text-fg`, `text-muted`, `border-line`, `bg-accent`…), `data-theme` dark (default) / light. Don't hard-code hex.
- Optional env: `GROQ_MODEL`, `LLM_FIRST_TOKEN_TIMEOUT_MS` (10000), `CHAT_MAX_TOKENS` (1500), `NEXT_PUBLIC_AUTH_ENABLED`.

### 2026-11-06 - Search the live official sites whenever the dataset cannot answer
- **Problem**: live search (Tavily, `.gov.in`/`.nic.in` only) ran only when the dataset returned NOTHING. The dataset nearly always returns something, even for questions it cannot answer (Sukanya Samriddhi returned unrelated "Samriddhi" schemes), and its entries are short summaries: only 2 of 4,740 have APPLICATION PROCESS / REQUIRED DOCUMENTS sections. So "how do I apply / what documents / eligibility" questions were answered with "steps not available" even when the right scheme was found.
- **Fix**: `src/lib/retrieval-plan.ts` (`planRetrieval`) decides per question, from the user's OWN words (`detectIntents`, English/Hinglish/Hindi: apply, documents, eligibility, amount, contact, status): (1) is any dataset hit actually about the subject (`isRelevantDoc`: >=60% of the distinctive words in the TITLE/opening line; category words like "card"/"loan" ignored; words deep in a description don't count)? (2) does it contain what was asked (`coversIntent`)? If not, `RAGEngine.retrieveUncached` searches the official sites live and answers from them; the scheme's own entry (if relevant) goes first as context. Irrelevant dataset hits are DROPPED (never fed to the model). If live search finds nothing: relevant dataset entry, else no sources (the prompt then points to myscheme.gov.in / india.gov.in). "Check my status" always goes live. Recency questions still go live first.
- `api/chat/route.ts` passes `intentText` (user's wording) and `liveQuery` (keeps "apply" etc.; the dataset query strips them). The retrieval cache key now includes the intents.
- Measured on 21 realistic questions (6 answerable from the snapshot, 15 not): 21/21 decisions as expected. Tests: `retrieval-plan.test.ts`, `live-fallback.test.ts` (each branch).
- **Cost note**: Tavily "advanced" search costs 2 credits per attempt (tracked in `tavily_usage`); more questions now go live. Free plan = 1,000 credits/month. Repeats within 15 minutes are served from the cache.
### 2026-11-06 - Same question, different answer by language / in an existing thread
- **Symptom**: PM Kisan steps appeared with English selected, but with Hinglish selected (same thread) the sources were unrelated and the answer said it could not find PM-KISAN.
- **Real cause (not the language)**: `buildRetrievalQuery` joined the last 3 user messages. Asking the same question again doubled the text and PM-KISAN dropped out of the top 3; a new topic after an unrelated question blended both topics.
- **Fixes** (all measured on the real dataset; right scheme in top 3):
  - `chat-request.ts`: a self-contained question is searched ALONE; only a genuine follow-up (`isFollowUpQuestion`: no subject of its own, or "it/this/iske") gets earlier turns, de-duplicated.
  - `ai/hinglish.ts`: Hinglish cleanup now DROPS "Yojna/Yojana" (translating it to "scheme" was as noisy: "PM Kisan scheme" missed, "PM Kisan" hit) and Hindi pointer words ("iske"). Hinglish 3/14 -> 13/14.
  - `ai/search-query.ts` (`normalizeSearchQuery`, used by `api/chat/route.ts`): also strips English question framing ("What is", "How do I", "Tell me about", "What documents are needed for"). English 9/14 -> 13/14 ("What is PM-KISAN?" used to miss).
  - `title-match.ts` + `LocalVectorStore.searchWithTitleBoost`: schemes whose title contains every distinctive word of the question are promoted (the embedding model is weak at exact names: "Ayushman Bharat" never returned its own scheme). Skipped when >6 titles match (too broad, e.g. "pension"); soft words like "card" are dropped on a second pass. Title hits skip the similarity threshold.
- **Hindi/Hinglish answers cut off mid-way (about half of them)**: `[GoogleGenerativeAI Error]: Failed to parse stream` from the `@google/generative-ai` library, on multi-byte Devanagari split across network chunks (English was fine). Found by running the real question through the adapter with `/api/internal/providers?probe=1&gemini_models=...&q=...&reply=hi`. Fix: `src/lib/ai/gemini.ts` now calls the REST streaming endpoint (`:streamGenerateContent?alt=sse`) and parses SSE itself (`parseGeminiSse`: streaming TextDecoder, buffers across chunks, ignores hidden `thought` parts, throws on in-stream errors / blocked responses so the router can fail over). The key goes in an `x-goog-api-key` header. Tests (`gemini-stream.test.ts`) cut Hindi at every byte. `@google/generative-ai` removed.
- **Still a gap**: Sukanya Samriddhi is not in the dataset (4,740 schemes); the dataset search returns something above the threshold so live search never runs. Idea: run live search when the top hit shares no title words with the question.
- `VECTOR_TOP_K` (3) was tested at 5 and 6: no gain once queries are cleaned, so unchanged.
### 2026-11-06 - Hinglish questions found the wrong schemes
- **Symptom**: "PM Kisan Yojna Ke liye kaise apply karein" returned unrelated schemes (Jharkhand skill centre, Haryana housing...) and the model said it could not find PM-KISAN's steps.
- **Cause**: retrieval embeds with an English-only model. Hindi typed in Latin letters was not translated (the LLM translation only runs for Devanagari), and the word "Yojna" overlaps hundreds of scheme titles: `PM Kisan Yojna apply` matched random "Yojna" schemes while `PM Kisan scheme apply` found PM-KISAN.
- **Fix**: `src/lib/ai/hinglish.ts` (`looksHinglish`, `normalizeHinglishQuery`), applied in `api/chat/route.ts` before retrieval: drops Hindi filler words, translates ~60 common words, turns Yojna/Yojana into "scheme". Rule-based on purpose (no network call, cannot time out). English queries are untouched (needs a clear Hindi function word to trigger). Measured on the real dataset, 14 realistic Hinglish questions: right scheme in the top 3 for **3 -> 12**. Tests: `hinglish.test.ts`.
- **Remaining misses are dataset gaps**, not this step: Sukanya Samriddhi is not among the 4,740 schemes, and Pradhan Mantri Awas Yojana is only present as a component. The dataset search returns *something* above the 0.35 similarity threshold for such questions, so the live-search fallback (which only runs when the dataset returns nothing) never fires. Possible follow-up: also try live search when the top hit's title shares no words with the question.
- The answer language follows the language selector (English by default), not the language typed.
### 2026-11-06 - "How do I apply for X?" answered with a refusal
- **Symptom**: asking e.g. "How do I apply for UP scholarship?" produced "No. InBridge is an independent assistant..." and "InBridge cannot apply for anything..." instead of an answer. Retrieval was fine (the right scheme was the first source).
- **Cause**: two unconditional lines in `src/lib/ai/system-prompt.ts` (the persona's "No. InBridge is an independent assistant" line and the "InBridge cannot apply for anything" rule) were over-applied by the lighter Gemini Flash-Lite model, which read a how-to question as a request to act for the user.
- **Fix**: persona line is now only for "are you official?"; replies must not open with a disclaimer or "No"; how-to questions are explained (or, when the sources lack steps, the matching schemes and official pages are named); refusal is reserved for requests that ask InBridge to act on the user's behalf. Tests in `system-prompt.test.ts`.
- **Retrieval tweak**: `expandStateAbbreviations` (`src/lib/rag-engine.ts`) spells out capitalised `UP`/`TN`/`WB` before searching, because the dataset says "Uttar Pradesh" in full ("UP scholarship" had matched Uttarakhand). `MP`/`AP`/`HP` are deliberately not expanded (ambiguous). Tests: `state-abbreviations.test.ts`.
- **Data limit (not fixed)**: the bundled myScheme snapshot has only a ~400-character summary per scheme (no application steps), and live government search did not return Uttar Pradesh's own scholarship portal. So step-by-step answers for many schemes are limited by the sources, and the model is told not to invent URLs or steps.

### 2026-11-06 — "The answer service is busy" (intermittent)
- **Cause**: only Groq is configured on Vercel (telemetry shows every real request served by `groq`, a `timeout` error on it, and no failover events ever). The router tried each configured provider once, so a single Groq timeout/429 with no fallback surfaced as the `provider_unavailable` card. Retrieval (sources) had already succeeded, which is why the sources showed but the answer did not.
- **Fix** (`src/lib/ai/router.ts`): `attemptPlan` gives a *lone* provider a second attempt inside the same request (not counted as a failover); several providers: unchanged. The per-attempt first-token cap stays 18 s (a first try can ride out Groq's 429 back-off; the retry gets what is left of the 35 s budget = maxDuration 60 - 25 reserve). I briefly lowered it to 12 s and reverted: two 12 s waits made a rate-limited Groq fail at ~25 s. Tests in `router.test.ts` (437 pass).
- **Measured on production after the fix**: questions 25 s apart: 4/4 OK, first text 1-2 s. Rapid burst of 4: 4/4 OK but first text 5.7 / 19.1 / 26.6 s (Groq throttling; the Groq `timeout` counter rose by 2 and the retry rescued both, which would previously have been the 'busy' card).
- **Honest limit**: with Groq as the only provider, bursts of questions can still be throttled (free-tier tokens-per-minute). The retry only absorbs one-off blips.
- **Permanent fix still needs the owner**: add a second provider key on Vercel (`GOOGLE_GEMINI_API_KEY` from Google AI Studio and/or `ANTHROPIC_API_KEY`), then redeploy the frontend. Check `GEMINI_MODEL` is a current model id (default `gemini-2.0-flash` is unverified). To see why Groq failed: Vercel -> Logs, search `LLM provider failed before first token` (shows kind: timeout / rate_limit / api_error).

### 2026-11-01 — Vector store (4,740 schemes) works on Vercel
- **Root cause**: `faiss-node`'s native binary isn't traced into the Vercel function (`Could not locate the bindings file`), so `FaissStore.load` always failed and every query went to Tavily.
- **Fix**: `src/lib/vector-search.ts` — pure-JS reader + brute-force L2 search over the *same* `vector_store/faiss.index` (IndexFlatL2, 4,740 × 384) and `docstore.json`; identical scores to FaissStore, ~100 ms/query. `faiss-node` is no longer loaded at runtime (still used by `scripts/generate-vector-store-faiss.js` to build the index).
- **Embedding model shipped in repo**: `models/Xenova/all-MiniLM-L6-v2/` (q8, 23 MB, sha256 matches HF). fp32 (90 MB) is too big for git; q8 query embeddings match the fp32-built index at cosine ~0.99 and retrieve the same top docs. Falls back to HF hub download into `/tmp` if `models/` is missing. **If the index is rebuilt with a different model, update `models/` too.**
- **Bundling** (`next.config.ts`): force-include `models/**` and onnxruntime's linux/x64 binary; exclude other platforms, GPU providers, onnxruntime-web, faiss-node. `/api/chat` trace ≈ 127 MB (limit 250 MB). Dockerfile copies `models/`.
- Tests: `src/lib/__tests__/vector-search.test.ts` (includes a real-index retrieval test).

### 2026-11-01 — Live government search (Tavily) actually returns results
- **Root cause (from Vercel runtime logs)**: Tavily was called on every query but returned 0 results with no error — `include_domains` was `[".gov.in", ".nic.in"]` (leading dot). Combined with the FAISS failure below, every answer had empty context and the model replied "I cannot browse the live internet".
- **Fix** (`src/lib/rag-engine.ts`): new `searchGovPortals()` — searches with `includeDomains: ["gov.in","nic.in"]`, retries unrestricted with `site:` hints if empty, and re-checks every result with `isGovUrl()` so only `.gov.in`/`.nic.in` pages reach the LLM. Logs `Tavily search completed` with raw vs gov result counts. Recency queries (`isRecencyQuery`: latest/new/2026/deadline/नवीनतम…) go to live search *before* the static vector store. Tests: `src/lib/__tests__/gov-search.test.ts`.
- **Still open**: FAISS vector store fails on Vercel — `faiss-node` native binary (`node_modules/faiss-node/build/Release/*`) isn't traced into the function bundle, and the transformers.js embedding model also needs onnxruntime + a writable cache. Until fixed, all queries are answered from live Tavily search.
